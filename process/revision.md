# 수정 프로세스

> "다음", "수정하자", "○장 작업" 등 장별 원고 작업 요청에 쓴다. 매 장마다 아래 순서를 반복한다.
> 진행·파일 관리는 📒 오스발트가 맡는다.

## 읽을 자료
`meta/style.md` → 대상 장과 직전·직후 `meta/chapters.md` 요약 → 대상 장의 `reviews/` 수정사항(있으면) → 대상 장 원문 전체(`manuscript/chapters/`의 해당 장 파일) → 관련 캐릭터.
작업 대상 장과 단계는 이미 읽은 `STATUS.md`에서 고른다.

## 순서
1. **기존 수정사항 검토 (📒 오스발트 단독)**
   - 대상 장의 `reviews/` 수정사항을 오스발트가 한 건씩 꺼내 사용자와 검토한다. 사용자가 반영 / 보류 / 폐기를 정한다.
   - 반영으로 정한 건은 수정안을 제시하고 승인받은 뒤 해당 장 파일에 반영한다.
   - 처리한 건(반영·폐기)은 수정사항 목록에서 지운다. 보류는 남긴다.
   - 검토할 수정사항이 없으면 바로 2로 간다.
   - 이 단계에서는 🐺 카시안·🪶 지젤·🦉 루시엔·🍃 노엘 등 검토 역할 인물을 등장시키지 않는다.
2. **검토모드 (상시 4인 + 관련 인물)**
   - 상시 4인에 더해, 대상 장에 실제로 등장하거나 편지·회상·사건·관계로 직접 얽힌 관련 인물을 필요한 범위에서 초대한다. 상시 4인만 기계적으로 부르지 않는다.
   - 1에서 반영한 내용이 들어간 해당 장 전체를 처음부터 끝까지 **누락 없이** 읽으며, 각자 역할에 맞게 새 수정사항을 찾는다.
   - 검토가 끝나면 초대 인물은 돌려보낸다.
   - 원문은 임의로 줄이거나 `(...)`로 생략하지 않는다. 길면 여러 구간으로 나누되 순서대로 전부 보여 준다.
3. **결과 저장 (📒 오스발트)**
   - 검토모드에서 나온 수정사항을 대상 장의 `reviews/` 파일에 **추후 수정사항**으로 저장한다. 이번 회차에 바로 고치지 않는다.
   - 원고가 바뀌었으면 `meta/chapters.md` 요약을 원고에 맞춘다.
   - `STATUS.md`의 현재 위치를 다음 장으로 옮긴다.
4. **다음 장**으로 넘어가 1부터 다시 시작한다.

STATUS에 명시된 이번 세션의 예외가 있으면 그 예외를 따른다.

## 검토모드 역할
- 🐺 카시안 = 흐름
- 🪶 지젤 = 셈
- 🦉 루시엔 = 정황
- 🍃 노엘 = 설명이 길어 장면·행동·사물이 더 필요한 곳

초대 인물은 자기가 직접 얽힌 사건·관계·말투를 중심으로 짚는다.
각 인물은 자기 담당을 우선하고 다른 역할을 빼앗지 않는다. 노엘은 배경 소개나 편지·칙령 원문처럼 필요한 설명은 지루하다는 이유만으로 줄이지 않는다.
기존에 기록된 제안은 보존하되 노엘에게 새 제안 역할을 추가하지 않는다.
원문을 부분별로 인용해 읽으며 그 자리에서 짚고, 끝에 역할별 정리를 붙인다.
지적할 것이 없으면 억지로 만든다거나 분량을 채우지 않는다.

## 수정안 작성 기준
- 수정 전 해당 문장의 앞뒤 문맥을 읽는다.
- 사건·정보·인물 의도를 보존한다.
- 한 문장을 고치기 위해 주변 문단 전체를 불필요하게 갈아엎지 않는다.
- 원문의 약간 거친 개성, 이상한 농담, 미묘한 반복은 이유가 있으면 남긴다.
- 대체 문장은 원고의 기존 어휘와 호흡을 먼저 따른다.
- 확신이 낮으면 성격이 다른 선택지를 짧게 제시할 수 있다.
- 수정안은 앞뒤 문단과 함께 제시하며 새로 들어가는 문장은 굵게 표시한다.
- 사용자 승인 뒤에만 수정본으로 취급한다. 활성 Claude 세션에서는 승인된 수정이 Artifact에 먼저 누적될 수 있으며, GitHub 정본 반영은 체크포인트 때 한꺼번에 한다.
- 사용자가 유지하기로 한 문장은 수정사항으로 다시 기록하지 않는다.
