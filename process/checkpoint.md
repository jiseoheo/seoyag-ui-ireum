# 저장·체크포인트

> 체크포인트를 만들 때, 끝인사·모델 교대 때 읽는다. 무엇을 저장할지의 기준은 `START.md` "저장 기준"에 있다.
> 진행·파일 관리는 📒 오스발트가 맡는다.

## 언제·어디에
- 활성 세션 중에는 승인된 수정과 보류 후보를 Artifact/대화 작업 상태에 누적할 수 있다. 승인 하나마다 GitHub write를 반복하지 않는다.
- 체크포인트는 다음 때 만든다: 모델을 Claude↔GPT로 바꾸기 전, 세션 종료 전, 사용량이 거의 찼을 때, 사용자가 저장을 요청했을 때, 장을 완료했을 때.
- 체크포인트에서는 승인된 원고를 `manuscript/chapters/`의 해당 장 파일, 확정 지속 설정을 `canon/*`, 다음 시작점과 장별 상태를 `STATUS.md`에, 장별 승인 결과·보류 후보를 `reviews/`에 반영한다. 장을 완료했다면 `meta/chapters.md`도 갱신한다.
- 체크포인트는 가능한 한 한 번의 일관된 묶음으로 커밋한다. 다음 모델은 그 커밋만으로 이어갈 수 있어야 한다.

## 체크포인트 원칙
GitHub `jiseoheo/seoyag-ui-ireum`의 `main`은 모델 교대와 세션 종료 때 서로 넘겨받는 영구 체크포인트다.
평소 주 작업은 Claude Project + 현재 세션의 Artifact에서 이어간다. 승인된 작은 수정마다 GitHub를 갱신하지 않는다.
GPT로 교대하거나 세션을 닫기 전에는 현재 세션의 승인 결과와 미완료 상태를 GitHub에 체크포인트로 반영한다.
다음 모델은 Artifact나 이전 채팅을 전제로 하지 않고 최신 GitHub 체크포인트에서 시작한다.
쓰기 직전에는 현재 main이 체크포인트 기준에서 바뀌었는지만 확인하고, 바뀌었으면 최신 변경을 먼저 대조한다.
저장소 접근이 실패하면 실패 사실을 알리고 확인되지 않은 최신 상태를 추측하지 않는다.

## Artifact 사용 원칙
- Claude Project에서는 Artifact를 현재 세션의 주 작업판으로 적극 사용한다. 원고 수정안 비교, 승인된 수정 누적, 검토 위치, 보류 후보를 한 세션 안에서 이어가는 데 쓴다.
- Artifact는 영구 정본이 아니다. 모델 교대·세션 종료 전에 반드시 GitHub 체크포인트로 필요한 내용을 옮긴다.
- 체크포인트가 끝난 뒤 다음 모델은 Artifact를 읽지 않아도 이어갈 수 있어야 한다.
- 캐릭터 잡담과 즉흥 설정은 필요할 때만 Artifact에 적고, 사용자가 확정하지 않은 내용은 GitHub CANON으로 옮기지 않는다.
- 한 세션에서는 가능한 한 같은 Artifact를 계속 갱신해 중복 컨텍스트를 줄인다.

## Claude Code 전달
- Claude Project가 직접 GitHub에 쓰지 못할 때 Claude Code는 체크포인트 저장 담당이다. 승인 하나마다 호출하지 않는다.
- 모델 교대·세션 종료·장 완료 등 체크포인트 시점에 현재 세션의 승인 결과를 한꺼번에 전달한다.
- 전달문에는 기준 main 커밋 SHA, 변경 대상 파일, 승인된 기존 내용과 변경 내용, 미완료·보류 상태, 건드리지 않을 범위, 완료 후 확인할 결과를 포함한다.
- Claude Code는 작업 직전 기준 SHA와 현재 main을 비교하고, main이 바뀌었으면 최신 변경을 먼저 대조한다.
- GPT, Claude, Claude Code 등 어떤 AI가 GitHub에 쓰더라도 **별도 작업 브랜치나 PR을 만들지 않고 `main`에 직접 커밋한다.**
- 원고·CANON·STATUS·서비스·운영 문서를 포함한 모든 저장 대상은 `main`을 단일 쓰기 대상으로 삼는다.
- 쓰기 직전 현재 `main`을 확인하고, 기준 SHA 이후 변경이 있으면 최신 변경을 먼저 대조한 뒤 충돌 없이 반영한다.
- 사용자가 명시적으로 브랜치나 PR을 요청한 경우에만 예외로 한다.

## 종료 / 모델 교대
끝인사가 분명하거나 다른 모델로 옮길 때는 먼저 체크포인트가 필요한지 확인한다.
현재 세션에서 승인된 변경이 GitHub에 아직 없으면 체크포인트를 만든 뒤, 다음 시작점만 짧게 확인한다.
새로 확정했는데 아직 CANON에 반영되지 않은 내용이 있으면 체크포인트에 포함한다.
이미 승인·반영된 내용은 다시 묻지 않는다.
긴 작업일지나 자동 세션 기록은 만들지 않는다.
Claude→GPT, GPT→Claude 교대 시 별도 인수인계 문서를 만들지 않는다. 최신 GitHub main과 STATUS가 인수인계다.
