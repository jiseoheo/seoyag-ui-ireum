# [서약의 이름으로] 정본 규칙

## 목적
Claude와 GPT가 작품 사실, 작업 상태, 아이디어, 즉흥 설정을 섞지 않도록 기준을 정한다.

## 작품 사실의 우선순위
1. 실제 원고 문장: `manuscript/current.html`
2. 확정된 캐릭터·인터뷰 규칙: `meta/characters.html`
3. 명시적으로 확정된 작가 결정과 수정 이력: `meta/worklog.html`
4. 작가 성향·응답 선호: `meta/author-notes.md`
5. 미확정 기획: `meta/ideas.md`
6. 일회성 대화 기록: `sessions/`

`meta/chapter-summaries.md`와 `CURRENT_STATE.md`는 탐색·운영용 파생 자료이며 작품 사실의 정본이 아니다.

## 작업 상태의 기준
- Revision Issue의 완료/미완료 상태와 장 진행 상태: Notion Revision Issues / Chapters
- 현재 대화가 어디서 시작할지 보여 주는 빠른 캐시: `CURRENT_STATE.md`
- 수정 이유, 과거 결정, 상세 이력: `meta/worklog.html`

셋이 어긋나면 상태값은 Notion을 먼저 확인하고, 이유와 이력은 worklog로 검증한다.
`CURRENT_STATE.md`는 정본을 덮어쓰지 않는다.

## 충돌 처리
- 같은 사실이 서로 다르면 더 최근의 명시적 작가 확정을 우선한다.
- 원고 본문과 메모가 충돌하면 본문을 자동 수정하지 않는다. 차이를 알려 주고 확인한다.
- 과거 메모는 현재 정본을 자동으로 덮어쓰지 않는다.
- 자료에 없는 사실을 기억으로 재구성하지 않는다.

## 정본 승격
다음 표현은 지속 규칙 또는 정본 승격 의사로 본다.
- "유지해"
- "확정"
- "앞으로 이렇게"
- "설정으로 넣어"
- "이걸로 하자"

단, 사용자가 가정·농담·임시안이라고 명시하면 승격하지 않는다.

## 인터뷰 중 즉흥 창작
- 캐릭터 인터뷰·잡담에서 캐붕 없는 소소한 에피소드 창작은 허용한다.
- 기본적으로 PLAYGROUND이며, 세션 기록에만 둘 수 있다.
- 사용자가 유지·확정 의사를 밝힌 경우에만 캐릭터/세계관 정본으로 옮긴다.
- 즉흥 내용 때문에 기존 원고를 소급 수정하지 않는다.

## 수정 반영
- 원고 수정안은 앞뒤 문맥과 함께 보여 준다.
- 원고 본문은 사용자가 승인한 뒤에만 변경한다.
- 변경 후 GitHub 커밋을 남긴다.
- 장 상태·수정거리·타임라인처럼 검색이 필요한 상태값은 Notion에 동기화한다.
- 현재 시작점이 달라지면 `CURRENT_STATE.md`도 짧게 갱신한다.

## 현재 정정 사례
- "황후는 없음"은 폐기된 표현이다.
- 현재 정본: 황후는 과거에 존재했으나 사망했고 사인은 불명이다.
- 따라서 현재 시점에 황후가 주최하는 행사는 없으며, 4장은 "황궁의 다과회"로 처리한다.

## 장별 문맥 요약
- `meta/chapter-summaries.md`는 장거리 문맥을 빠르게 탐색하기 위한 파생 인덱스다.
- 전체 흐름, 복선, 감정선, 반복 사물을 찾을 때 먼저 사용한다.
- 실제 사실·문장은 항상 원고와 확정 설정에서 재확인한다.
- 감상모드의 독자 체감은 임시 관찰로 취급하고, 검토모드가 끝난 뒤 사실 확인 결과와 함께 최종 요약에 반영한다.
- 원고 수정으로 사건, 복선, 감정선, 관계 변화, 다음 장 연결이 달라지면 해당 요약도 같은 작업에서 갱신한다.
- 과거 장의 독자 체감은 실제 재감상 없이 임의로 소급 작성하지 않는다.

## 종료 시 대조
- 세션 종료 신호가 오면 현재 대화와 외부 정리를 대조한다.
- 대화에는 있으나 외부 정리에 없는 내용, 또는 기존 정리와 충돌하는 내용은 자동으로 정본 승격하지 않는다.
- 이미 같은 대화에서 명시적으로 승인되어 반영된 내용은 재승인 대상이 아니다.
